# Case study: Coal Shipments

## Контекст

Я самостоятельно разработал MVP внутренней системы учёта авто- и ЖД-отгрузок.
Цель — заменить общий Excel-файл управляемым веб-интерфейсом, где несколько
пользователей могут работать с данными без потери контроля над правами,
документами и историей изменений.

## Решение

Backend на Django разделён на доменные приложения: отгрузки, импорт, документы,
аудит, справочники и системные операции. Я использовал явные Django permissions
вместо неявной проверки `is_staff`; документы хранятся вне БД, а импорт XLSX
имеет preview, валидацию и защиту от небезопасного XML-содержимого.

Для эксплуатации добавлены Docker runtime, healthcheck, отдельный scheduler для
очереди backup/restore, контроль целостности backup и release gate. Фронтенд
собран на Django templates и Tailwind CSS, без тяжёлого SPA-слоя.

## Качество и ограничения

Проект покрыт unit/regression и Playwright critical-flow тестами, а также
проверяется Ruff и CSS drift check. Я не называю его production-системой:
предстоят version-bound проверки на целевой инфраструктуре и нагрузочный импорт.

## AI-assisted workflow

Claude Code и OpenAI Codex использовались как инструменты разработки: для
декомпозиции крупных задач, проверки вариантов реализации, подготовки тестов и
документации. Агентные результаты не принимались автоматически: изменения
проверялись тестами, линтером, review diff и ручными сценариями. В приложении нет
LLM-интеграции — это важно не смешивать с AI-assisted процессом разработки.

## Что показывает этот кейс

- самостоятельность: от постановки прикладной задачи до воспроизводимой поставки;
- backend: Django, модель прав, миграции, работа с файлами и реляционной БД;
- инженерное качество: тестирование, secure-by-default настройки, release checks;
- продуктовая работа: таблицы, фильтры, импорт Excel и понятные роли пользователей.
